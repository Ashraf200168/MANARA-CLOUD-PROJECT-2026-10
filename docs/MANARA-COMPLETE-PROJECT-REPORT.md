## 1. الملخص التنفيذي

بدأ Manara كموقع يعمل على خادم خاص بقاعدة SQLite، وكان الوصول إليه من الإنترنت يتم مؤقتًا عبر ngrok. احتوى النظام منذ البداية على الطلاب والامتحانات والنتائج والكتب وبنك الأسئلة والفوائد والأسئلة الشرعية والدعم ولوحة الشيخ.

جرى لاحقًا استنساخ النسخة العاملة بدل إيقافها، ثم بُنيت نسخة سحابية مستقلة بالكامل:

- نُقلت قاعدة البيانات من SQLite إلى PostgreSQL في Supabase.
- نُقلت الكتب إلى Supabase Storage.
- بُني API آمن باستخدام Supabase Edge Functions.
- نُشرت الواجهة على Cloudflare Pages.
- نُقلت بيانات الإنتاج القديمة وتحققت أعداد الجداول والكتب.
- أُنشئت PWA أولًا، ثم استُبدلت عمليًا بتطبيق Flutter حقيقي لأن المطلوب كان تطبيقًا بواجهة أصلية وذاكرة محلية، وليس اختصارًا للموقع.
- أضيفت تجربة طالب تعمل بأسلوب offline-first.
- أضيفت لوحة شيخ كاملة داخل التطبيق، تشمل إنشاء الامتحان وتعديله وإدارة جميع أجزاء المنصة.
- أضيفت شهادة تفوق تلقائية للامتحان الذي يحدده الشيخ.
- أضيف نظام نسخ احتياطي مشفر ومتحقق منه إلى OneDrive وGitHub.
- أضيف مستودع GitHub عام يحتوي المصدر والوثائق وآخر APK، مع فرع منفصل لأحدث نسخة مشفرة.
- أضيف وضع Full Hands-Off لمراقبة الموقع والـAPI والنسخ وGitHub وإعادة المحاولة تلقائيًا.

النتيجة النهائية هي نظام سحابي لا يعتمد على بقاء VPS أو ngrok أو الكمبيوتر الشخصي مفتوحًا لخدمة الطلاب. الكمبيوتر الحالي يؤدي دور المراقبة والنسخ الاحتياطي فقط.

## 2. المرحلة الأولى: النظام المحلي

### البنية الأصلية

- خادم محلي/VPS يشغّل التطبيق.
- قاعدة بيانات SQLite في ملف `manara.db`.

### الوظائف الموجودة في النسخة الأصلية

- صفحة عامة للبرنامج.
- تسجيل الطلاب وإنشاء معرف دائم لكل طالب.
- صفحة الطالب ونتائجه.
- الامتحانات والتعيينات والمحاولات والإجابات.
- بنك أسئلة.
- كتب وفوائد ونصائح.
- أسئلة شرعية وإجابات الشيخ.
- دعم فني مرتبط بصفحة الطالب.
- لوحة إدارة للشيخ.
- تصدير ومتابعة النتائج.

### قرار الاستمرارية أثناء النقل

كان الشرط الأساسي ألا تتوقف النسخة العاملة أثناء بناء السحابة. لذلك:

1. بقيت النسخة القديمة تعمل خلال النقل.
2. أُخذت لقطة سليمة من SQLite والملفات.
3. بُنيت النسخة السحابية في مشروع منفصل.
4. اختُبرت النسخة الجديدة قبل الاعتماد عليها.

لم يُجرَ تعديل مباشر خطر على قاعدة الإنتاج القديمة أثناء عملية النقل.

## 5. المشكلات التي ظهرت أثناء نشر Supabase وحلولها

### تعذر اتصال قاعدة البيانات

ظهر خطأ مهلة اتصال مع Supabase pooler أثناء وجود حادثة تقنية في الخدمة، مع تأثير VPN والاتصال. جرى الانتظار وإعادة التنفيذ باستخدام كلمة مرور قاعدة البيانات الصحيحة، ثم نجح:

```text
Finished supabase db push.
```

### تحذير Docker

ظهر التحذير:

```text
WARNING: Docker is not running
```

لم يمنع هذا نشر Edge Function لأن Supabase CLI استطاع رفع ملفات الدالة مباشرة.

### خطأ تشغيل دالة `scrypt`

ظهرت مشكلة توافق في استيراد `scrypt` داخل بيئة Deno/Supabase. عُدلت طبقة الحماية، ثم أعيد نشر `manara-api`. بعد التصحيح ظهرت سجلات `booted` بدل خطأ worker، وعادت استدعاءات API إلى الحالة السليمة.

### CORS

بعد نشر Cloudflare Pages أُضيف رابط Pages الفعلي إلى الأصل المسموح به، ثم أعيد نشر API. بذلك أصبح الموقع السحابي يتصل بالخلفية دون كشف مفاتيح سرية.

## 10. سياسة العمل دون اتصال

التطبيق يعمل بأسلوب **offline-first**، وليس offline-only.

| الوظيفة | تعمل دون إنترنت | تحتاج الإنترنت |
|---|---:|---:|
| عرض آخر معلومات الطالب | نعم | للتحديث |
| عرض آخر النتائج | نعم | لجلب نتيجة جديدة |
| عرض الفوائد المحفوظة | نعم | لجلب فوائد جديدة |
| عرض فهرس الكتب المحفوظ | نعم | للتحديث |
| قراءة كتاب تم تنزيله | نعم | لا |
| تنزيل كتاب جديد | لا | نعم |
| فتح امتحان جديد | لا | نعم |
| حفظ وتسليم الامتحان | لا | نعم |
| مراجعة نتيجة أو رد جديد | آخر نسخة فقط | نعم للتحديث |
| سؤال الشيخ والدعم | قراءة المحفوظ | نعم للإرسال والاستقبال |

عند بداية التطبيق تظهر مزامنة مرئية بدائرة تحميل صغيرة في شريط الحالة، ثم تتحول الحالة إلى بيانات محدثة أو بيانات محفوظة وفق الاتصال.

## 16. النسخ الاحتياطي المشفر

### المحتوى

- جميع جداول Supabase التشغيلية.
- ملفات الكتب في `manara-books`.
- manifest بأعداد الجداول والملفات.
- بصمة SHA-256 لكل كتاب ولملف النسخة.

### طريقة الحماية

- تنسيق الملف: `MNBAK001`.
- اشتقاق المفتاح: `scrypt` مع salt عشوائي.
- التشفير: `AES-256-GCM`.
- IV عشوائي لكل نسخة.
- Authentication tag لاكتشاف كلمة المرور الخاطئة أو تلف الملف.
- لا يُستبدل ملف نسخة موجود.
- تُفك النسخة مباشرة إلى ملف تحقق، ثم تُقارن البصمة قبل إعلان النجاح.

### الجدول والاحتفاظ

- الفحص يوميًا وعند تسجيل الدخول.
- إنشاء نسخة عندما تمر نحو 70 ساعة على آخر نجاح.
- يحتفظ OneDrive بآخر 10 نسخ، أي قرابة شهر حسب الجدول الحالي.
- مجلد الحفظ:

```text
%USERPROFILE%\OneDrive\Manara Cloud Backups
```

### آخر نسخة موثقة وقت التقرير

| البند | القيمة |
|---|---|
| الملف | `manara-cloud-20261027-102501.mnbak` |
| الحجم | 15,598,853 بايت |
| SHA-256 | `D0B84B9C988EF04AA4024754AE0B4596A4FECFED46F61D259BDAE4424A3A6B99` |
| النتيجة | `BACKUP SUCCESS` |

كلمة الاستعادة غير مخزنة في GitHub، وهي مطلوبة للاستعادة على جهاز جديد.
