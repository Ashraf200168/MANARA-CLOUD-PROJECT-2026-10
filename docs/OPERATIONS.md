# التشغيل الذاتي الكامل

يعتمد وضع **Full Hands-Off** على جهاز Windows الحالي بصفته مشرفًا احتياطيًا للخدمات السحابية. لا يحتاج الموقع أو تطبيق Android إلى أن يبقى الجهاز مفتوحًا كي يعملا؛ Cloudflare وSupabase يواصلان خدمة الطلاب بصورة مستقلة. الجهاز مطلوب فقط للفحص الدوري والنسخ المشفر ورفع GitHub.

## ما يعمل تلقائيًا

- فحص موقع Cloudflare وواجهة Supabase API عند تسجيل الدخول، وفي 09:00 و19:00 يوميًا.
- إعادة فحص الاتصال ثلاث مرات قبل تسجيل العطل.
- إنشاء نسخة مشفرة ومتحقق منها عندما تصبح أحدث نسخة أقدم من 76 ساعة.
- حفظ النسخ في OneDrive وفق سياسة الاحتفاظ الحالية.
- رفع أحدث نسخة مشفرة فقط إلى فرع `encrypted-backup`.
- مزامنة المصدر المنقح والوثائق وآخر APK مع فرع `main`.
- تسجيل نتيجة موحدة في `.tools/maintenance/last-status.json`.
- إظهار تنبيه بعد ثلاثة فحوص فاشلة متتالية فقط، ثم إعادة المحاولة تلقائيًا.
- تشغيل المراقبة من خلال `RUN-MANARA-HANDSOFF.cmd` الذي يستعيد ملفات المراقبة والمزامنة من تاريخ Git تلقائيًا إذا حذفتها حماية Windows أو أداة خارجية.

## التفعيل مرة واحدة

شغّل الملف التالي من Windows:

```text
START-MANARA-FULL-HANDSOFF.bat
```

ينشئ الإعداد مهمة Windows باسم `Manara Full Hands-Off Maintenance` ويجري فحصًا كاملًا مباشرة. لا يطلب مفاتيح جديدة؛ يستخدم إعداد النسخ الاحتياطي المحمي بـDPAPI وتسجيل GitHub الموجودين أصلًا.

## ما لا يُنشر آليًا عن قصد

تعديلات الميزات الجديدة أو قواعد البيانات لا تُنشر إلى الإنتاج لمجرد حفظ ملف محلي. هذا حاجز أمان يمنع وصول كود غير مكتمل إلى الطلاب. بعد اختبار أي إصدار جديد، يتم نشر Supabase وCloudflare وAPK بالطريقة الموثقة في [دليل النشر](DEPLOYMENT.md)، وبعدها يتولى وضع Hands-Off المراقبة والنسخ والمزامنة.

## حدود الجهاز

- الموقع والتطبيق يظلان متاحين حتى لو كان الكمبيوتر مطفأ.
- المهام المحلية لا تعمل أثناء إطفاء الكمبيوتر، لكنها تعمل عند أول تسجيل دخول بفضل `StartWhenAvailable`.
- إذا بقي الكمبيوتر مطفأ أكثر من ثلاثة أيام، ستُنشأ النسخة التالية عند تشغيله وتوفر الاتصال.
- كلمة استعادة النسخة ومفتاح Supabase لا يُرفعان إلى GitHub.

## تشخيص سريع

- الحالة الأخيرة: `.tools/maintenance/last-status.json`
- سجل المراقبة: `.tools/maintenance/maintenance.log`
- سجل النسخ: `.tools/backup/backup.log`
- سجل المصدر: `.tools/github-public/publish.log`
- سجل النسخة المشفرة: `.tools/github-backup-publish/publish.log`

وجود ملف `MANARA-ATTENTION.txt` داخل مجلد النسخ يعني أن ثلاثة فحوص متتالية فشلت. يحذف المراقب هذا الملف تلقائيًا بعد عودة جميع الفحوص إلى الحالة السليمة.
