# النسخ الاحتياطي والاستعادة

## السياسة الحالية

- المهمة المجدولة تفحص النسخ يوميًا وعند تسجيل الدخول.
- تنشئ نسخة جديدة عندما يمر نحو 70 ساعة على آخر نسخة ناجحة.
- تشمل جداول Supabase وكتب `manara-books`.
- تشفر النسخة بكلمة مرور محلية قبل حفظها.
- تتحقق من فك التشفير وسلامة الأرشيف قبل إعلان النجاح.
- يحتفظ النظام بآخر 10 نسخ.

المجلد الافتراضي:

```text
%USERPROFILE%\OneDrive\Manara Cloud Backups
```

## تشغيل نسخة يدويًا

شغّل `RUN-MANARA-BACKUP-NOW.cmd`. النجاح النهائي يجب أن يتضمن:

```text
BACKUP SUCCESS
```

## إعداد جهاز جديد

شغّل `START-MANARA-BACKUP-SETUP.bat`، وأدخل Supabase secret key وكلمة مرور النسخ عندما يطلبهما البرنامج. الأحرف المخفية أثناء الإدخال سلوك مقصود. لا ترسل القيمتين في محادثة أو بريد.

## الاستعادة

شغّل `RESTORE-MANARA-BACKUP.cmd` وحدد ملف `.mnbak`. تفك الأداة النسخة إلى مجلد استعادة منفصل ولا تستبدل الإنتاج مباشرة. راجع البيانات والملفات أولًا، ثم نفذ استيرادًا مخططًا إلى مشروع Supabase جديد أو فارغ.

## GitHub

بموافقة مالك المشروع على مشاركة بيانات الطلاب، تنشر الأتمتة **أحدث ملف مشفر فقط** في فرع `encrypted-backup` من المستودع. لا تُنشر البيانات المفكوكة ولا مفتاح Supabase ولا كلمة استعادة النسخة. يعاد إنشاء الفرع بعملية `force-with-lease` كل مرة بحيث يبقى commit واحد قابل للوصول ولا يتراكم تاريخ ثنائي كبير.

هذه الموافقة لا تجعل كلمة المرور غير مهمة: لأن المستودع عام، استخدم كلمة استعادة طويلة وفريدة واحفظها خارج الكمبيوتر. تحتاج مزامنة GitHub تسجيل دخول واحدًا عبر Git Credential Manager؛ بعد ذلك تعمل المهمة المجدولة دون تدخل ما دامت صلاحية الحساب محفوظة.

## اختبار التعافي

مرة كل شهر:

1. اختر نسخة حديثة.
2. فكها في مجلد اختبار.
3. طابق عدد الجداول والكتب والبصمات مع ملف manifest.
4. نفذ استعادة تجريبية إلى مشروع غير إنتاجي عند الإمكان.
5. سجل تاريخ الاختبار ونتيجته.
